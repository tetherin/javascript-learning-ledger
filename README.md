# JavaScript Learning Ledger

A persistent progress tracker for a structured JavaScript and full-stack engineering learning program.

## How this ledger works
- Each learning session contains exactly 10 useful development/JavaScript tips.
- Topics progress from fundamentals to practical usage, edge cases, advanced concepts, interviews, and production engineering.
- Learning is interactive: predict outputs, debug code, solve case studies, explain concepts, and implement small features.
- A topic is mastered only after demonstrated understanding, not merely because it was explained.
- Use the revision queue to revisit topics and avoid unnecessary repetition.

## Repository map
- progress/ — dashboard, mastery evidence, revision queue, and session history.
- javascript/ — JavaScript topics organized by concept.
- interview-preparation/ — output prediction, conceptual, case-based, and coding questions.
- full-stack/ — React, Node.js, TypeScript, databases, and authentication/security.
- session-reports/ — records of completed sessions.

## Session workflow
1. Read the dashboard, mastery tracker, revision queue, and recent session history.
2. Select 10 items appropriate to the learner's current level and priorities.
3. Teach with runnable examples, explain trade-offs and edge cases, then ask questions without revealing answers prematurely.
4. Record actual responses, misconceptions, corrections, and evidence of mastery.
5. Update topic notes, dashboard, tracker, revision queue, and session report.
6. Verify changes before reporting that the ledger was updated.

No formal baseline assessment has been completed. Existing knowledge is unassessed, not mastered or weak by assumption.
