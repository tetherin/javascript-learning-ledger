## The 10 concepts taught

### 1. Object.assign uses source Get and target Set semantics
- Object.assign(target, ...sources) copies own enumerable string and Symbol properties from each source.
- It reads source properties, so source getters can execute.
- It writes to the target using ordinary set semantics, so target setters (including inherited setters) can execute.
- It mutates and returns the target object.
- It is not a descriptor-preserving copy.

Example:
```js
const proto = {
  set theme(value) {
    console.log("setter:", value);
  }
};
const target = Object.create(proto);

const returned = Object.assign(target, { theme: "dark" });

console.log(returned === target); // true
console.log(Object.hasOwn(target, "theme")); // false
```

### 2. Object spread creates own data properties on the new object
- In an object literal, spread copies own enumerable source properties into the new object.
- If the source property is an accessor, its getter is evaluated to obtain the value.
- The copied property on the result is an ordinary own data property; the source getter/setter descriptor is not preserved.
- An inherited setter on the new object's prototype is not invoked by the spread property's definition.
- Later literal properties overwrite earlier copied values.

Example:
```js
const proto = {
  set theme(value) {
    console.log("setter:", value);
  }
};
const target = Object.create(proto);
const spread = { ...target, theme: "light" };

console.log(Object.hasOwn(spread, "theme")); // true
console.log(spread.theme); // "light"
```

### 3. Source getters execute during both Object.assign and object spread
- Both mechanisms obtain enumerable own source property values, which can invoke a getter.
- Object.assign then sets the obtained value on its target.
- Object spread defines a data property with the obtained value on the new object.
- Descriptor copying with Object.getOwnPropertyDescriptors preserves the getter function instead of evaluating it during descriptor retrieval.

Example:
```js
let reads = 0;
const source = Object.defineProperty({}, "value", {
  enumerable: true,
  get() {
    reads++;
    return 7;
  }
});

const spreadCopy = { ...source };
console.log(reads); // 1
console.log(Object.getOwnPropertyDescriptor(spreadCopy, "value"));
// { value: 7, writable: true, enumerable: true, configurable: true }
```

### 4. Object.assign can leave a partially mutated target when it throws
- Assignment is performed property by property.
- If a later target write fails (for example, a non-writable property or a throwing setter), Object.assign throws TypeError.
- Earlier successful writes are not rolled back.
- Treat Object.assign as a sequence of writes, not a transaction.

Example:
```js
const target = {};
Object.defineProperty(target, "locked", {
  value: 0,
  writable: false,
  enumerable: true
});

try {
  Object.assign(target, { first: 1, locked: 2 });
} catch (error) {
  console.log(error instanceof TypeError); // true
}

console.log(target.first); // 1 — earlier write remains
console.log(target.locked); // 0
```

### 5. Object merge order and nested replacement are separate concerns
- In `{ ...defaults, ...overrides }`, later properties win.
- A shallow merge replaces an entire nested property; it does not recursively merge nested objects.
- The same caveat applies to Object.assign({}, defaults, overrides).
- If headers need to be merged, merge that nested object explicitly.
- This prevents accidentally dropping Content-Type or carrying over an unintended request-specific value.

Example:
```js
const defaults = {
  timeout: 5000,
  headers: { "Content-Type": "application/json" }
};
const overrides = {
  headers: { authorization: "Bearer A" }
};

const shallow = { ...defaults, ...overrides };
const safe = {
  ...defaults,
  ...overrides,
  headers: { ...defaults.headers, ...overrides.headers }
};

console.log(shallow.headers); // only authorization
console.log(safe.headers); // Content-Type and authorization
```

### 6. Descriptor-preserving copies retain accessors but remain shallow
- Object.getOwnPropertyDescriptors returns descriptors for all own string and Symbol properties, including non-enumerable properties.
- Object.create(Object.getPrototypeOf(source), descriptors) creates a new object with the same prototype and those descriptors.
- Retrieving descriptors does not call an accessor getter; the getter is copied as a function.
- Reading the copied accessor later invokes that getter.
- Nested object values remain shared references; this is not a deep clone.

Example:
```js
let reads = 0;
const source = {};
Object.defineProperty(source, "value", {
  enumerable: true,
  get() {
    reads++;
    return 7;
  }
});

const copy = Object.create(
  Object.getPrototypeOf(source),
  Object.getOwnPropertyDescriptors(source)
);

console.log(reads); // 0
console.log(copy.value); // 7
console.log(reads); // 1
```

### 7. Non-configurable data-property transition is one-way
- A non-configurable data property that is still writable may have its value changed and may transition from writable:true to writable:false.
- After writable becomes false, its value cannot be changed.
- A non-configurable property cannot be deleted, made configurable, have enumerability changed, or switch between data and accessor descriptor kinds.
- In ES modules and other strict-mode code, forbidden assignments throw TypeError.

Example:
```js
const item = {};
Object.defineProperty(item, "id", {
  value: 1,
  writable: true,
  configurable: false
});

Object.defineProperty(item, "id", { value: 2 }); // allowed
Object.defineProperty(item, "id", { writable: false }); // allowed
// Changing value to 3 now throws TypeError.
```

### 8. Object.hasOwn distinguishes absent from present-with-undefined
- Object.hasOwn(obj, key) returns true for an own property even when its value is undefined or null.
- The in operator also sees inherited properties.
- For request parameters, use own-property presence when the API's default should apply only if a parameter is absent.
- Do not use truthiness to decide whether a property exists.

Example:
```js
const query = { limit: undefined };

console.log(Object.hasOwn(query, "limit")); // true
console.log("limit" in query); // true

delete query.limit;

console.log(Object.hasOwn(query, "limit")); // false
```

### 9. Validate Express query values from unknown before conversion
- Express documents req.query as user-controlled and untrusted; its structure depends on the configured query parser.
- A query value can be absent or have a shape other than a string, so validate before calling string or numeric methods.
- TypeScript unknown forces runtime narrowing before use.
- Check object shape, own-property presence, primitive type, syntax, safe-integer status, and range in that order.
- This example accepts only positive decimal integer strings from 1 to 100; this is an explicit API policy, not a universal parsing rule.

Example:
```ts
function parseLimit(query: unknown): number {
  if (
    query === null ||
    typeof query !== "object" ||
    Array.isArray(query)
  ) {
    throw new Error("Invalid query");
  }

  if (!Object.hasOwn(query, "limit")) {
    return 20;
  }

  const value = (query as Record<string, unknown>).limit;

  if (
    typeof value !== "string" ||
    !/^[1-9]\\d*$/.test(value)
  ) {
    throw new Error("Invalid limit syntax");
  }

  const limit = Number(value);

  if (!Number.isSafeInteger(limit) || limit > 100) {
    throw new Error("Limit must be between 1 and 100");
  }

  return limit;
}
```

### 10. Promise.allSettled preserves input order but does not limit concurrency
- Promise.allSettled waits for every input promise to settle and returns an outcome for each.
- The outcomes are in input order, not completion order.
- Promise.all rejects when an input rejects, while allSettled reports each fulfilled/rejected outcome.
- Neither API limits how many operations are started.
- For large workloads, use a bounded worker pool or batches; fixed-size batches are simpler but wait for the slowest item in each batch before starting the next.

Example:
```js
const outcomes = await Promise.allSettled(
  ids.map(id => fetchUser(id))
);
```

For a simple concurrency cap of five:
```js
const outcomes = [];

for (let i = 0; i < ids.length; i += 5) {
  const batch = await Promise.allSettled(
    ids.slice(i, i + 5).map(id => fetchUser(id))
  );
  outcomes.push(...batch);
}
```
