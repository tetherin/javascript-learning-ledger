## The 10 concepts taught

### 1. Enumeration API review: different property sets
- Object.keys(obj): own, enumerable, string-keyed properties.
- Object.getOwnPropertyNames(obj): all own string-keyed properties, including non-enumerable.
- Reflect.ownKeys(obj): all own string and Symbol keys, enumerable or not.
- for...in: enumerable string keys from the object and its prototype chain.
- This revisits the original Session 01 enumeration misconception.

Example:
```js
const proto = { role: "admin" };
const record = Object.create(proto);
record.name = "Ansh";
Object.defineProperty(record, "internal", { value: 1 });
const marker = Symbol("marker");
record[marker] = true;

console.log(Object.keys(record)); // ["name"]
console.log(Object.getOwnPropertyNames(record)); // ["name", "internal"]
console.log(Reflect.ownKeys(record)); // ["name", "internal", Symbol(marker)]
```

### 2. Object.defineProperty defaults, strict mode, and return value
- When creating a property, omitted writable, enumerable, and configurable flags default to false; omitted value defaults to undefined for a data descriptor.
- Ordinary assignment creating a property normally makes it writable, enumerable, and configurable.
- Object.defineProperty(target, key, descriptor) returns the same target object.
- In strict mode (including ES modules), assigning to a non-writable data property throws TypeError; in non-strict code, the assignment is ignored.
- Object.defineProperty uses property-definition semantics and does not invoke an existing setter merely to define/reconfigure a property.

Example:
```js
const settings = {};
const returned = Object.defineProperty(settings, "mode", {
  value: "dark"
});

console.log(returned === settings); // true
console.log(Object.keys(settings)); // []
console.log(Object.getOwnPropertyDescriptor(settings, "mode"));
// { value: "dark", writable: false, enumerable: false, configurable: false }
```

### 3. Non-configurable descriptor invariants
- configurable:false prevents deletion, changing enumerability, changing property kind (data/accessor), or freely changing descriptor attributes.
- A non-configurable data property that is still writable can have its value changed and can transition writable:true to writable:false.
- That writable transition is one-way; once writable:false, its value cannot be changed.
- In strict mode, assignment to a non-writable property throws TypeError.

Example:
```js
const item = {};
Object.defineProperty(item, "id", {
  value: 1,
  writable: true,
  configurable: false
});

Object.defineProperty(item, "id", { value: 2 }); // allowed
Object.defineProperty(item, "id", { writable: false }); // allowed
// A later attempt to set value: 3 throws TypeError.
```

### 4. Accessor descriptors and reconfiguration
- Reading an accessor property invokes its getter; assigning invokes its setter.
- A descriptor is either data-shaped (value/writable) or accessor-shaped (get/set), never both.
- Object.defineProperty reconfigures the property definition; it does not call the old setter to assign a value.
- When redefining a configurable existing property, omitted descriptor attributes retain their existing values rather than resetting to creation defaults.
- Accessors should not hide asynchronous I/O or expensive work.

Example:
```js
let backing = 0;
const box = {};
Object.defineProperty(box, "value", {
  configurable: true,
  enumerable: true,
  get() { return backing; },
  set(next) { backing = next; }
});

box.value = 3; // invokes setter
Object.defineProperty(box, "value", {
  value: 10,
  writable: true
}); // replaces accessor with data property; does not call setter

console.log(backing); // 3
console.log(box.value); // 10
```

### 5. Descriptor-preserving shallow copy vs spread vs structuredClone
- Object.getOwnPropertyDescriptors(obj) returns all own property descriptors, including non-enumerable and Symbol properties.
- Object.create(Object.getPrototypeOf(obj), Object.getOwnPropertyDescriptors(obj)) makes a new object with the same prototype and own descriptors.
- This is a shallow copy: nested object-valued properties still reference the same nested objects.
- Spread copies own enumerable properties into ordinary data properties; reading source accessors can invoke getters, and the original descriptors/prototype are not preserved.
- structuredClone is for deep cloning supported data, not for preserving prototypes and property descriptors; functions and some other values are not cloneable.

Example:
```js
const descriptorCopy = Object.create(
  Object.getPrototypeOf(source),
  Object.getOwnPropertyDescriptors(source)
);
```

### 6. Object.assign vs object spread: setter behavior
- Object.assign(target, source) mutates and returns target.
- Object.assign reads source values and writes them to target using ordinary set semantics, so source getters and target setters can run.
- Object spread in an object literal creates a new object and defines own data properties from source enumerable own properties; it does not invoke an inherited setter on the new target for the copied property.
- Both are shallow and copy enumerable own string and Symbol properties; neither preserves source descriptors or prototype.
- Object.assign may partially mutate its target before throwing if a later property write fails.

Example:
```js
const proto = {
  set theme(value) {
    console.log("setter:", value);
  }
};

const target = Object.create(proto);
const returned = Object.assign(target, { theme: "dark" });
const spread = { ...target, theme: "light" };

console.log(returned === target); // true
console.log(Object.hasOwn(target, "theme")); // false
console.log(spread.theme); // "light"
```

### 7. Integrity levels and inspection methods
- Object.preventExtensions prevents new own properties; existing configurable properties may still be deleted and existing writable values changed.
- Object.seal also prevents deletion and reconfiguration; existing writable data values can still change.
- Object.freeze additionally makes own data properties non-writable.
- Object.isExtensible, Object.isSealed, and Object.isFrozen inspect these integrity states.
- All three operations are shallow and return the same object; accessors can still run their setters and mutate external/closure state.

### 8. Map vs Object.create(null) for dynamic dictionaries
- Map supports keys of any value type, exposes size, and iterates entries in insertion order.
- An ordinary object coerces property keys to strings or Symbols and inherits Object.prototype behavior.
- Object.create(null) creates a dictionary with no prototype; it still uses property keys (strings/Symbols) and has no built-in size property.
- Map is often the clearest choice for dynamic key-value collections; null-prototype objects are useful when an object-shaped dictionary is required.
- Neither structure validates untrusted values or makes unsafe downstream merging safe by itself.

Example:
```js
const counts = new Map();
counts.set("role", 1);
counts.set({ source: "api" }, 2);
console.log(counts.size); // 2

const dictionary = Object.create(null);
dictionary["__proto__"] = "ordinary data key";
console.log(Object.hasOwn(dictionary, "__proto__")); // true
```

### 9. Express req.query and TypeScript unknown
- Express documents req.query as user-controlled and untrusted; its shape depends on the configured query parser.
- A query parameter may be absent, a string, an array, or a nested object; do not assume it is always a string.
- At trust boundaries, TypeScript unknown is safer than any because operations require runtime narrowing.
- Validate object shape, own-property presence, primitive type, syntax, safe-integer status, and range before use.
- A reusable value parser can validate one value without mutating the original request object.

Example:
```ts
function parseLimitValue(value: unknown): number {
  if (
    typeof value !== "string" ||
    !/^[1-9]\d*$/.test(value)
  ) {
    throw new Error("limit must be a positive decimal integer string");
  }

  const parsed = Number(value);

  if (!Number.isSafeInteger(parsed) || parsed > 100) {
    throw new Error("limit must be between 1 and 100");
  }

  return parsed;
}
```
This helper validates the value only; the caller must separately validate query shape and own-property presence.

### 10. Promise.all vs Promise.allSettled and concurrency policy
- Promise.all waits for all fulfillment values and rejects as soon as one input rejects; it does not cancel other operations that have already started.
- Promise.allSettled waits for every input to settle and returns ordered outcome objects with status plus value or reason.
- Mapping a large collection into Promise.all starts all mapped operations; it does not impose a concurrency limit.
- Use sequential for...of with await when ordering/rate constraints matter, or a bounded-concurrency worker/queue for large batches.
- Choose based on failure policy: fail the overall operation on any failure, collect partial outcomes, or process in controlled batches.

Example:
```js
const outcomes = await Promise.allSettled(
  ids.map(id => fetchUser(id))
);
```
