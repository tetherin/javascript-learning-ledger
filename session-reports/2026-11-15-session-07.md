### 1. Object.assign: own enumerable string and Symbol keys, source Get, target Set
- Object.assign copies own enumerable string-keyed and Symbol-keyed properties from each source.
- It reads source values (so enumerable getters can execute) and writes to the target (so target setters can execute).
- It mutates and returns the target.
- Object.keys() will not show Symbol keys even though Object.assign can copy enumerable Symbols.
- Reference: https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Object/assign

~~~js
const trace = Symbol("trace");
const source = {
  get token() {
    console.log("source getter");
    return "A";
  },
  [trace]: "copied"
};

const target = {
  set token(value) {
    console.log("target setter:", value);
  }
};

const result = Object.assign(target, source);
console.log(result === target);
console.log(Object.getOwnPropertySymbols(target).length);
~~~

### 2. Object.assign is not atomic
- Properties are processed sequentially.
- If a later target write fails, earlier successful writes remain.
- It has no transaction or rollback behavior; avoid mutating important shared state until inputs are validated.

~~~js
const target = {};
Object.defineProperty(target, "fixed", {
  value: 0,
  writable: false,
  enumerable: true
});

try {
  Object.assign(target, { saved: true, fixed: 1 });
} catch (error) {
  console.log(error instanceof TypeError);
}
console.log(target.saved); // earlier write remains
~~~

### 3. Shallow override precedence includes undefined
- Later top-level properties win.
- A later explicit undefined overwrites a default; it does not mean "leave the default unchanged."
- A later nested object replaces the earlier nested object unless the nested level is merged explicitly.
- Configuration APIs should define whether undefined means clear, ignore, or invalid.

~~~js
const defaults = { timeout: 5000, headers: { accept: "application/json" } };
const override = { timeout: undefined, headers: { authorization: "Bearer X" } };
const config = { ...defaults, ...override };
console.log(config.timeout); // undefined
console.log(config.headers); // authorization only
~~~

### 4. Descriptor-preserving copies preserve behavior, not nested isolation
- Object.getOwnPropertyDescriptors() captures data/accessor descriptors without invoking getters to read their values.
- Object.create(Object.getPrototypeOf(source), descriptors) preserves the prototype and property descriptors.
- The operation is still shallow: object-valued descriptor values are copied by reference.
- Mutating a nested object through either copy can affect the other.
- References:
  - https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Object/getOwnPropertyDescriptors
  - https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Object/getOwnPropertyDescriptor

~~~js
const source = { nested: { count: 1 } };
const copy = Object.create(
  Object.getPrototypeOf(source),
  Object.getOwnPropertyDescriptors(source)
);
copy.nested.count++;
console.log(source.nested.count); // shared nested reference
~~~

### 5. Validate query records and own-property values separately
- unknown requires runtime narrowing before property access.
- Reject null, primitives, and arrays before reading query properties.
- For this parser-oriented example, other object values pass the initial shape check; the important own-property test still ignores inherited values. If an application requires strictly plain records, add an explicit prototype policy and adjust the inherited-object test to expect a shape error.
- Object.hasOwn distinguishes absent from present-but-undefined and ignores inherited values.
- Numeric syntax and numeric range are separate checks; Number("1.5") is valid conversion but may violate an integer pagination contract.

~~~ts
function isRecord(value: unknown): value is Record<string, unknown> {
  return value !== null &&
    typeof value === "object" &&
    !Array.isArray(value);
}

function parseLimit(query: unknown): number {
  if (!isRecord(query)) throw new Error("Invalid query");
  if (!Object.hasOwn(query, "limit")) return 20;

  const value = query.limit;
  if (typeof value !== "string" || !/^[1-9][0-9]*$/.test(value)) {
    throw new Error("Invalid limit");
  }

  const limit = Number(value);
  if (!Number.isSafeInteger(limit) || limit > 100) {
    throw new Error("Invalid limit");
  }
  return limit;
}
~~~

This example defines a strict policy: canonical positive decimal integer strings from 1 to 100, defaulting only when the own property is absent. The policy may need adjustment for a different API contract.

Reference: https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Object/hasOwn

### 6. A bounded worker pool must be tested as an invariant
- Promise.allSettled records outcomes; it does not limit how many tasks start.
- A fixed number of workers can claim indices synchronously, await one task at a time, and store results at the original index.
- A useful test measures the maximum number of active tasks, not just the final result array.
- Production concerns include database pool capacity, external rate limits, retries, cancellation, and backpressure.

~~~js
let active = 0;
let maxActive = 0;

async function task(id) {
  active++;
  maxActive = Math.max(maxActive, active);
  try {
    return await fetchUser(id);
  } finally {
    active--;
  }
}

// Pass task to a worker pool configured with concurrency 5.
// After completion, assert maxActive <= 5.
~~~

### 7. AbortSignal is one-shot; compose cancellation and timeout
- A signal becomes permanently aborted after its controller aborts; do not reuse it for a new request.
- AbortSignal.timeout(ms) creates a timeout signal.
- AbortSignal.any([...]) combines signals so the first abort wins.
- Distinguish user cancellation (often AbortError) from timeout (often TimeoutError).
- Cancellation is cooperative and does not prove that already-started server/database work was rolled back.
- References:
  - https://developer.mozilla.org/en-US/docs/Web/API/AbortSignal
  - https://nodejs.org/api/globals.html

~~~js
const userController = new AbortController();
const timeout = AbortSignal.timeout(5000);
const signal = AbortSignal.any([userController.signal, timeout]);

try {
  await fetch("/api/report", { signal });
} catch (error) {
  if (error instanceof Error && error.name === "AbortError") {
    // user/navigation cancellation
  } else if (error instanceof Error && error.name === "TimeoutError") {
    // timeout policy
  } else {
    throw error;
  }
}
~~~

### 8. Fetch response bodies are streams and normally consumed once
- HTTP 404/500 responses still fulfill fetch with a Response; inspect response.ok/status.
- response.json(), response.text(), and other body readers are asynchronous and consume the body.
- Do not call response.json() and then response.text() on the same consumed response.
- If two consumers genuinely need the body, clone the Response before reading; cloning large streams has memory/backpressure trade-offs.
- Check content-type if the API contract requires JSON, and handle malformed JSON separately from HTTP status errors.
- Reference: https://developer.mozilla.org/en-US/docs/Web/API/Fetch_API/Using_Fetch

~~~js
const response = await fetch("/api/users");
const contentType = response.headers.get("content-type") ?? "";

if (!response.ok) {
  throw new Error("HTTP " + response.status);
}
if (!contentType.includes("application/json")) {
  throw new TypeError("Expected JSON response");
}
const body = await response.json();
~~~

### 9. Express 5 only forwards Promises returned by the handler
- Express 5 forwards a thrown error or rejected Promise from a route/middleware that returns that Promise.
- An unreturned detached Promise is outside Express's automatic error chain.
- Use await/return for request-scoped work. For intentional background work, use a queue or explicitly handle the rejection; do not accidentally create an unhandled rejection.
- Error middleware uses (err, req, res, next), and should avoid leaking internal details.
- References:
  - https://expressjs.com/en/5x/guide/error-handling/
  - https://expressjs.com/en/guide/migrating-5/

~~~js
app.get("/users/:id", async (req, res) => {
  const user = await findUser(req.params.id);
  res.json(user);
});

// This detached work is NOT automatically tracked by Express:
app.post("/audit", (req, res) => {
  void writeAuditRecord(req.body); // needs an explicit failure policy
  res.sendStatus(202);
});
~~~

### 10. Test async rejection with assert.rejects, not assert.throws
- assert.throws is for a function that throws synchronously.
- assert.rejects is for an async function or Promise that rejects.
- node:test treats a returned rejected Promise as a failed test.
- Test boundary behavior and observable invariants, not implementation details alone.
- References:
  - https://nodejs.org/api/test.html
  - https://nodejs.org/api/assert.html

~~~js
import test from "node:test";
import assert from "node:assert/strict";

test("sync validation throws", () => {
  assert.throws(() => parseSyncValue(null), TypeError);
});

test("async validation rejects", async () => {
  await assert.rejects(
    () => loadAndValidate("bad-id"),
    /invalid/
  );
});
~~~
