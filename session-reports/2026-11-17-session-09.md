### 1. Object and array spread create shallow copies, not independent nested data

A shallow copy creates a new outer container while retaining references to nested objects and arrays.

~~~js
const original = {
  profile: { name: "Ansh" },
  tags: ["js"]
};

const copy = { ...original };

copy.profile.name = "changed";
copy.tags.push("ts");

console.log(original.profile.name);
console.log(original.tags);
console.log(copy !== original, copy.profile === original.profile);
~~~

Output:

~~~text
changed
[ "js", "ts" ]
true true
~~~

Object spread, array spread, and Object.assign() do not recursively clone nested values. This is why copying a React state object only at the top level and then mutating a nested object is still a mutation of shared state.

Use a path copy when changing nested state:

~~~js
const next = {
  ...original,
  profile: {
    ...original.profile,
    name: "Ada"
  }
};
~~~

The changed path gets new references; unchanged nested values may safely retain their references if they are treated immutably.

Reference: https://developer.mozilla.org/en-US/docs/Glossary/Shallow_copy

### 2. structuredClone() is a deep data clone, not a universal object-cloning mechanism

~~~js
const original = { name: "root" };
original.self = original;

const cloned = structuredClone(original);

console.log(cloned !== original);
console.log(cloned.self === cloned);
~~~

Output:

~~~text
true
true
~~~

The structured clone algorithm supports circular references and many built-in data types. It is useful when a supported data graph needs an independent copy.

But it does not preserve every JavaScript object feature:
- Functions cannot be cloned and cause a DataCloneError.
- Custom prototype chains are not generally reproduced.
- Property descriptors, getters, and setters are not preserved as descriptors.
- It is not a replacement for a domain-specific clone when class invariants or behavior matter.

~~~js
const source = {};
Object.defineProperty(source, "id", {
  value: 7,
  enumerable: true,
  writable: false
});

const clone = structuredClone(source);

console.log(Object.getOwnPropertyDescriptor(clone, "id").writable);
~~~

Output:

~~~text
true
~~~

The cloned data property is writable under the ordinary default descriptor, unlike the original. Choose the cloning strategy based on whether you need independent data or preservation of object behavior.

References:
- https://developer.mozilla.org/en-US/docs/Web/API/Window/structuredClone
- https://developer.mozilla.org/en-US/docs/Web/API/Web_Workers_API/Structured_clone_algorithm

### 3. A sparse-array hole is not the same as an explicit undefined value

~~~js
const sparse = ["a", , "c"];
const explicit = ["a", undefined, "c"];

console.log(1 in sparse, 1 in explicit);

let visited = 0;
const mapped = sparse.map(() => {
  visited++;
  return "x";
});

console.log(visited);
console.log(1 in mapped);

const spread = [...sparse];
console.log(1 in spread, spread[1]);
~~~

Output:

~~~text
false true
2
false
true undefined
~~~

A hole means that index 1 is absent. An explicit undefined means the property exists and its value is undefined.

Methods such as map(), filter(), and forEach() skip absent slots. Array iteration/spread reads the hole as undefined, so spreading a sparse array produces a dense position containing undefined.

This distinction can affect validation, serialization, indexing, and tests. Prefer dense arrays for application data unless sparse arrays are intentional.

Reference: https://developer.mozilla.org/en-US/docs/Web/JavaScript/Guide/Indexed_collections

### 4. Array.from() converts iterables and array-like values into a new dense array

~~~js
const input = {
  0: "A",
  2: "C",
  length: 3
};

const values = Array.from(input, (value, index) => {
  return String(index) + ":" + (value ?? "missing");
});

console.log(values);
~~~

Output:

~~~text
[ "0:A", "1:missing", "2:C" ]
~~~

Array.from() accepts an iterable or an array-like object with a length and indexed properties. It returns a new array. Its optional mapping callback runs as values are added, avoiding an intermediate array.

It does not recursively clone object elements; if an element is an object, its reference is retained unless the mapping callback copies it.

For a normal object that is neither iterable nor array-like, use Object.keys(), Object.values(), or Object.entries() according to the desired representation.

Reference: https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Array/from

### 5. flatMap() maps and flattens exactly one level

~~~js
const users = [
  { id: "u1", roles: ["read", "write"] },
  { id: "u2", roles: ["read"] }
];

const grants = users.flatMap(user =>
  user.roles.map(role => ({
    userId: user.id,
    role
  }))
);

console.log(grants);
~~~

Output:

~~~text
[
  { userId: "u1", role: "read" },
  { userId: "u1", role: "write" },
  { userId: "u2", role: "read" }
]
~~~

flatMap() is equivalent in result to map() followed by flat(1). It returns a new array and does not mutate the source array. It flattens one level only; deeper arrays remain nested.

It is useful for turning nested API relationships into rows such as user-role grants, order-line records, or route entries. For very large performance-sensitive transformations, benchmark against a loop rather than assuming flatMap() is always faster.

Reference: https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Array/flatMap

### 6. forEach() does not wait for async callbacks

~~~js
const ids = [1, 2, 3];

await ids.forEach(async id => {
  await saveUser(id);
});

console.log("finished");
~~~

This does not wait for all saveUser() calls. forEach() discards callback return values and itself returns undefined; awaiting undefined completes immediately while the callback Promises continue independently.

Choose the required execution policy:

Sequential:

~~~js
for (const id of ids) {
  await saveUser(id);
}
~~~

Concurrent:

~~~js
await Promise.all(ids.map(id => saveUser(id)));
~~~

Promise.all() starts all mapped operations and rejects when one rejects; it is not a concurrency limiter. For large batches, use a bounded worker pool and define a partial-failure policy.

Reference: https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Array/forEach

### 7. sort() mutates; toSorted() returns a new array, and numeric sorting needs a comparator

~~~js
const values = [9, 80, 100];

const sorted = values.toSorted((a, b) => a - b);

console.log(values);
console.log(sorted);
console.log(sorted === values);
console.log([9, 80, 100].sort());
~~~

Output:

~~~text
[ 9, 80, 100 ]
[ 9, 80, 100 ]
false
[ 100, 80, 9 ]
~~~

Without a comparator, sort() converts elements to strings and compares their UTF-16 code units. It does not perform numeric ordering by default.

sort() mutates and returns the same array. toSorted() returns a new array and leaves the source unchanged. The new array is still shallow: object elements remain shared references.

A numeric comparator should return a negative number, zero, or a positive number. For ascending numbers, (a, b) => a - b is the usual comparator.

References:
- https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Array/sort
- https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Array/toSorted

### 8. Object.entries() and Object.fromEntries() are not perfectly symmetric

~~~js
const marker = Symbol("marker");
const prototype = { inherited: true };
const record = Object.create(prototype);

record.name = "Ada";
Object.defineProperty(record, "hidden", { value: 1 });
record[marker] = 2;

console.log(Object.entries(record));
console.log(Object.hasOwn(record, "inherited"), "inherited" in record);

const rebuilt = Object.fromEntries([
  ...Object.entries(record),
  [marker, 2]
]);

console.log(Reflect.ownKeys(rebuilt));
~~~

Output:

~~~text
[ [ "name", "Ada" ] ]
false true
[ "name", Symbol(marker) ]
~~~

Object.entries() returns own enumerable string-keyed pairs only. It excludes inherited properties, non-enumerable properties, and Symbols.

Object.fromEntries() accepts an iterable of key-value pairs and can create Symbol-keyed properties. If duplicate keys occur, the later entry supplies the final value.

Use Object.hasOwn() when testing own-property presence; use in only when inherited properties should count.

References:
- https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Object/entries
- https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Object/fromEntries
- https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Object/hasOwn

### 9. Object.freeze() is shallow; immutable updates copy the changed path

~~~js
const state = Object.freeze({
  profile: {
    name: "Ada"
  }
});

state.profile.name = "Grace";

const next = {
  ...state,
  profile: {
    ...state.profile,
    name: "Lin"
  }
};

console.log(state.profile.name);
console.log(next.profile.name);
console.log(Object.isFrozen(state.profile));
~~~

Output:

~~~text
Grace
Lin
false
~~~

Object.freeze() prevents changes to the supplied object's own property structure and writable data values, but it does not recursively freeze nested objects.

For state updates, copy each object along the path being changed. Do not deep-clone the entire state automatically: unchanged immutable branches can retain identity, which is useful for reference-based change detection.

If deep immutability is required, define and test an explicit deep-freeze policy. A shallow freeze alone is not that guarantee.

Reference: https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Object/freeze

### 10. Map is usually safer than an ordinary object for arbitrary dynamic keys

~~~js
const permissions = new Map();

permissions.set("__proto__", "reader");
permissions.set({ id: 1 }, "admin");

console.log(permissions.get("__proto__"));
console.log(permissions.size);
console.log([...permissions.keys()]);
~~~

Output:

~~~text
reader
2
[ "__proto__", { id: 1 } ]
~~~

Map supports keys of any value type, preserves insertion order, and does not expose ordinary object prototype properties as entries. This makes it a useful choice for dictionaries keyed by untrusted or arbitrary values.

Trade-offs:
- Map uses set(), get(), has(), delete(), and size rather than object property syntax.
- JSON.stringify(new Map([["a", 1]])) produces "{}" by default; convert entries explicitly if JSON output is required.
- Ordinary objects remain convenient for fixed-shape records and JSON DTOs.
- Object.create(null) is another dictionary option when an object is required but inherited Object.prototype properties are unwanted.

Do not choose Map automatically for every record. Choose it when its key semantics and collection operations fit the data model.

Reference: https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Map
