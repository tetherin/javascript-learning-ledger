## The 10 concepts taught

### 1. Enumeration APIs expose different property sets
- Object.keys(obj): own, enumerable, string-keyed properties.
- Object.getOwnPropertyNames(obj): all own string-keyed properties, including non-enumerable ones.
- Reflect.ownKeys(obj): all own string and Symbol keys, enumerable or not.
- for...in: enumerable string keys from the object and its prototype chain.
- This directly revisits the Session 01 Q1 ownership/enumerability misconception.

Example:
```js
const proto = { inherited: true };
const row = Object.create(proto);
row.id = 7;
Object.defineProperty(row, "secret", { value: "hidden" });
const marker = Symbol("marker");
row[marker] = "symbol value";

console.log(Object.keys(row));              // ["id"]
console.log(Object.getOwnPropertyNames(row)); // ["id", "secret"]
console.log(Reflect.ownKeys(row));          // ["id", "secret", Symbol(marker)]
```

### 2. Separate ownership from enumerability
- The in operator checks the object and its prototype chain.
- Object.hasOwn(obj, key) checks direct ownership, whether enumerable or not.
- Object.prototype.propertyIsEnumerable.call(obj, key) checks direct ownership and enumerability.
- Object.hasOwn() is robust for null-prototype objects and objects that shadow hasOwnProperty.

Example:
```js
const proto = { role: "inherited" };
const user = Object.create(proto);
Object.defineProperty(user, "token", { value: "secret" });

console.log("role" in user); // true
console.log(Object.hasOwn(user, "role")); // false
console.log(Object.hasOwn(user, "token")); // true
console.log(Object.prototype.propertyIsEnumerable.call(user, "token")); // false
```

### 3. A property descriptor is metadata, not just a value
- Object.getOwnPropertyDescriptor(obj, key) returns the descriptor for an own property, or undefined if it is not own.
- Data descriptors use value/writable.
- Accessor descriptors use get/set.
- Both types use enumerable/configurable.
- Mutating the returned descriptor object does not reconfigure the original property.

### 4. Descriptor flags have defaults and invariants
- When Object.defineProperty() creates a property, omitted writable, enumerable, and configurable flags default to false.
- Ordinary assignment creating a new own property normally makes those flags true.
- A non-configurable property cannot be deleted or freely reconfigured. If it is a non-configurable data property that is still writable, its value may be changed and writable may be changed to false; it cannot then be changed back to true.
- Object.defineProperty() returns the original target object.

Example:
```js
const account = {};
Object.defineProperty(account, "id", {
  value: 42,
  enumerable: true,
  writable: true,
  configurable: false
});
```

### 5. Accessor descriptors compute or validate values
- A getter runs when the property is read; a setter runs when it is assigned.
- A descriptor is either a data descriptor or an accessor descriptor; do not combine value/writable with get/set.
- Use accessors for derived or controlled property behavior, not as a hidden substitute for asynchronous I/O or expensive work.

Example:
```js
let internalCount = 0;
const counter = {};

Object.defineProperty(counter, "count", {
  enumerable: true,
  configurable: true,
  get() {
    return internalCount;
  },
  set(value) {
    if (Number.isSafeInteger(value) && value >= 0) {
      internalCount = value;
    }
  }
});
```

### 6. Descriptor-preserving copies differ from spread and deep cloning
- Object.getOwnPropertyDescriptors(obj) collects all own property descriptors, including non-enumerable and Symbol-keyed properties.
- Object.create(Object.getPrototypeOf(obj), Object.getOwnPropertyDescriptors(obj)) creates a new object with the same prototype and own property descriptors.
- This is still a shallow copy: nested object values/references are not recursively cloned.
- Object spread copies own enumerable properties as values and does not preserve non-enumerable properties or original descriptors. This is different from the learner's earlier structuredClone() solution, which deep-clones supported data structures.

Example:
```js
const descriptorCopy = Object.create(
  Object.getPrototypeOf(source),
  Object.getOwnPropertyDescriptors(source)
);
```

### 7. Object integrity levels: preventExtensions, seal, freeze
- preventExtensions prevents adding own properties; existing properties can generally still be changed or deleted.
- seal also prevents deletion and reconfiguration, but existing writable data properties can still be changed.
- freeze additionally makes existing own data properties non-writable.
- These operations affect the object itself, not recursively every nested object; they return the same object.
- This is a substantive spaced review of Session 01's freeze/seal concept.

### 8. map/forEach and asynchronous work
- map returns an array of callback results; forEach discards callback return values and returns undefined.
- forEach does not await async callbacks.
- Use Promise.all(items.map(async ...)) for bounded concurrent work, or for...of with await for sequential work.
- In production, unbounded Promise.all across thousands of database/API calls can overload dependencies; use batching or a concurrency limit where needed.

Example:
```js
const results = await Promise.all(
  ids.map(id => fetchUser(id))
);
```

### 9. sort/toSorted and copy depth
- sort mutates the original array and returns the same array reference.
- toSorted returns a new array, but the copy is shallow; object elements remain shared references.
- Default Array sort compares string representations. Supply a comparator for numeric or domain-specific ordering.
- Comparator logic should be consistent (including antisymmetry and transitivity).
- This is a spaced review of Session 01's array mutation distinction.

Example:
```js
const ordered = users.toSorted((a, b) =>
  a.createdAt.localeCompare(b.createdAt)
);
```

### 10. Treat dynamic keys and Express query data as untrusted
- for...in includes inherited enumerable keys; it is usually the wrong default for copying an untrusted request object.
- Ordinary objects inherit special behavior such as the __proto__ setter. Unsafe merging or nested dynamic writes can change prototypes and create prototype-pollution vulnerabilities.
- For arbitrary key-value dictionaries, Map or Object.create(null) can avoid inherited Object.prototype keys; still validate keys and nested structures.
- Express documents req.query as user-controlled and untrusted. Validate shape, own required fields, types, syntax, ranges, and allowed keys before use.
- Revisit the earlier getLimit(query) bug: using "limit" in query accepts inherited properties; Number(value) alone does not enforce positive integer syntax or a maximum.

Example safe dictionary:
```js
const lookup = new Map();
for (const key of Object.keys(untrustedInput)) {
  lookup.set(key, untrustedInput[key]);
}
```

### Exercise B — bug-finding and practical implementation

```js
function getLimit(query) {
  if ("limit" in query) {
    return Number(query.limit);
  }
  return 20;
}
```

- rejects null, arrays, and non-object input;
- only accepts an own limit property;
- accepts only positive decimal-integer strings;
- requires a safe integer from 1 through 100;
- returns 20 only when limit is genuinely absent;
- does not mutate query.

Explain the validation order. Also explain why for...in or blindly copying untrusted keys into {} can be dangerous. Choose Map or Object.create(null) for a dynamic dictionary and justify the choice.
