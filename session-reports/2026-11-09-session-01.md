## Learning objective

Build a precise mental model for working with JavaScript objects and arrays, especially when transforming configuration or API data in a backend.

## The 10 tips

### 1. Choose the right object projection: keys, values, or entries

```js
const settings = { theme: "dark", retries: 3 };

Object.keys(settings);   // ["theme", "retries"]
Object.values(settings); // ["dark", 3]
Object.entries(settings);// [["theme", "dark"], ["retries", 3]]
```

These methods return arrays. They inspect the object's own enumerable string-keyed properties. Use keys when you need names, values when you need values, and entries when you need both.

### 2. Object.entries() is not a complete inventory of an object

It excludes inherited properties, non-enumerable properties, and symbol-keyed properties. It returns only own enumerable string-keyed pairs.

```js
const proto = { inherited: true };
const settings = Object.assign(Object.create(proto), { region: "ap-south-1" });
Object.defineProperty(settings, "internal", {
  value: "hidden",
  enumerable: false,
});
settings[Symbol("trace")] = "abc";

console.log(Object.entries(settings));
// [["region", "ap-south-1"]]
```

Also remember property ordering: integer-index-like string keys are visited in ascending numeric order before other string keys, which generally retain creation order. Do not use object key order as a substitute for an explicitly ordered business data structure.

### 3. Destructure entries to write clear object loops

```js
const limits = { free: 10, pro: 100 };

for (const [plan, limit] of Object.entries(limits)) {
  console.log(plan, limit);
}
```

The loop receives a two-item array for each pair. This is especially useful when validating or transforming key-value configuration. Prefer `for...of` when you need early `break` or `continue`; `forEach` cannot be exited with a normal `break`.

### 4. Filter and rebuild an object with entries() and fromEntries()

```js
const input = {
  name: "Asha",
  role: "admin",
  debug: true,
};

const publicProfile = Object.fromEntries(
  Object.entries(input).filter(([key]) => key !== "debug")
);

console.log(publicProfile); // { name: "Asha", role: "admin" }
```

Think of this as a pipeline: object → pairs → array operations → new object. `Object.fromEntries()` consumes an iterable of key-value pairs and creates a new object. If duplicate keys occur in the iterable, the later pair wins.

### 5. Use Object.hasOwn() when ownership matters

```js
const proto = { inherited: "from prototype" };
const record = Object.assign(Object.create(proto), { name: "Mira" });

"inherited" in record;          // true
Object.hasOwn(record, "inherited"); // false
Object.hasOwn(record, "name");      // true
```

The `in` operator checks the object and its prototype chain. `Object.hasOwn()` checks only direct properties, including non-enumerable own properties. It also works with null-prototype objects and avoids relying on a possibly overridden `hasOwnProperty` method. Use it when processing untrusted or externally supplied records.

### 6. Object.assign() mutates its target and performs a shallow copy

```js
const target = { retries: 1 };
const source = { retries: 3, timeout: 5000 };

const result = Object.assign(target, source);

console.log(target);       // { retries: 3, timeout: 5000 }
console.log(result === target); // true
```

Later sources overwrite earlier ones. The target object is modified and returned. It copies own enumerable properties (including symbols), reads source values, and writes them to the target; getters and setters can therefore run. Use `Object.assign({}, source)` when a new top-level object is wanted, not when a deep clone is required.

### 7. Object spread also makes only a shallow copy

```js
const defaults = {
  headers: { accept: "application/json" },
};

const copy = { ...defaults };
copy.headers.accept = "text/plain";

console.log(defaults.headers.accept); // "text/plain"
```

The outer object is new, but the nested `headers` object is shared. This is a frequent source of accidental state mutation in React and backend configuration code. Copy each nested level you intend to change, or use an appropriate structured-cloning strategy when the data is cloneable. Neither spread nor Object.assign is a universal deep-clone operation.

### 8. Object.freeze() and Object.seal() are different—and shallow

- `Object.seal(obj)`: prevents adding/removing properties and makes existing properties non-configurable; writable existing values may still change.
- `Object.freeze(obj)`: also makes existing data properties non-writable.
- Both return the same object and are shallow: nested objects are not automatically frozen or sealed.

```js
const config = Object.freeze({
  retries: 3,
  headers: { accept: "application/json" },
});

config.retries = 5; // fails or is ignored depending on strictness
config.headers.accept = "text/plain"; // nested object is still mutable
```

Freezing is not a substitute for validation, defensive copying, or runtime security boundaries.

### 9. Use map() for transformation; use forEach() for side effects

```js
const ids = [2, 4, 6];

const labels = ids.map(id => `user-${id}`);
// ["user-2", "user-4", "user-6"]

const result = ids.forEach(id => console.log(id));
// result is undefined
```

`map()` returns a new array containing callback results. `forEach()` returns `undefined` and is intended for side effects. A common bug is using `forEach()` when you expect an array to be returned. Neither method automatically makes nested values immutable.

### 10. sort() mutates; toSorted() returns a new array

```js
const scores = [8, 100, 20];

scores.sort((a, b) => a - b);
console.log(scores); // [8, 20, 100] — original changed

const names = ["Zara", "Aman", "Neha"];
const sortedNames = names.toSorted();

console.log(names);       // original order unchanged
console.log(sortedNames);// ["Aman", "Neha", "Zara"]
```

Without a comparator, `sort()` sorts elements by string conversion, so numeric arrays can surprise you (for example, 100 can come before 20). Use a numeric comparator for numbers. Use `toSorted()` when you need a sorted copy and your target runtime supports it.

const data = Object.assign(Object.create(proto), { 10: "ten", 2: "two", region: "IN" });

### Q2 — Find the bug

```js
const defaults = {
  headers: { accept: "application/json" },
};

function makeRequestConfig(overrides) {
  const config = { ...defaults };
  config.headers.authorization = overrides.token;
  return config;
}
```

Why can calling this function affect later requests? Show a safe fix for this specific nested object.

### Q3 — Practical implementation

Given an object `query`, return a new object containing only the keys `page`, `limit`, and `sort`. Convert `page` and `limit` to numbers, and omit keys whose input value is `undefined`. Use `Object.entries()`, array methods, and `Object.fromEntries()`. Mention one validation you would add before using this in an API.

### Q4 — Conceptual interview question

Explain the difference between `Object.hasOwn(obj, key)`, `key in obj`, and `Object.keys(obj).includes(key)`. Which would you use to check whether an untrusted input record explicitly supplied a field, and why?
